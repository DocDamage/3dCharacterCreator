# P01 — Reference Conflict Report

**Status:** Complete
**Priority rule:** Original high-detail concepts > additional individual screens > contact sheets > reasoned UX decisions.

The references are broadly coherent in visual direction, but they represent multiple information architectures and levels of detail. These are the material conflicts and the canonical resolutions for P02–P04.

| ID | Conflict | Observed in | Canonical resolution |
|---:|---|---|---|
| C01 | The original concepts use a gold-outlined application shell, while several additional screens use blue as the dominant selected/navigation accent. | Original screens 01–07; additional screens 01–32 | Keep warm gold for brand, primary actions, focus rings, and high-priority selection. Reserve blue for informational, progress, and secondary active states. P03 tokens must make the semantic distinction explicit. |
| C02 | Navigation is shown as granular tabs (`Base`, `Body`, `Head`, `Hair`, `Clothing`, `Accessories`, `Weapons`, `Preview`) in one concept, grouped workspaces in the sitemap, and a `Create > Design > Animate > Test > Export` pipeline in the alternate contact sheet. | Original 01, 02, 03; alternate contact sheet | Use the sitemap groups as the global IA. Preserve granular task names as local tabs/rail items and expose the pipeline as a progress/context layer, not a competing navigation model. |
| C03 | Character creation and animation are composed in one large integrated workspace in Original 02, but split into separate screens in Additional 07–13 and the alternate contact sheet. | Original 02; additional 07–13; alternate contact sheet | Keep separate canonical boards/routes for focused tasks, with linked flows and a shared preview shell. Do not duplicate the same controls in both workspaces. |
| C04 | The preview reference names `SK_Mannequin` and `ABP_Player`, while retargeting/animation references use a mannequin source and a hero/character target. The repository uses Manny/Quinn source assets and a Sidekick target preview. | Original 01–02; additional 07–12; repository asset/evidence map | Treat Manny/Quinn as source content and Sidekick as the target preview. Surface source/target labels and compatibility state in retargeting; never imply that a source mannequin is the final preview mesh. |
| C05 | The original advanced body/face concept combines body and face morph authoring with region selection, symmetry, comparison, and portrait presets. Additional Body and Face screens present simpler, separated slider views. | Original 05; additional 02–03 | Make the combined advanced creator the canonical high-detail workflow. Use Body and Face as entry-level task views that link into advanced region editing and preserve shared state. |
| C06 | Weapon Setup & IK combines sockets, IK targets, motion warp, animation set preview, and validation, while the additional set splits animation, retargeting, skeleton, and gameplay responsibilities across separate screens. | Original 06; additional 11–15 | Keep Weapon Setup & IK as the user-facing guided workflow. Link to technical assistants for detailed edits and return validation results to the weapon workflow. |
| C07 | Validation and export are one integrated screen in Original 07, while Export Options, Loading, and Error Dialog are separate additional states. | Original 07; additional 28–30 | Use Validation & Export as the primary workspace. The original preview controls remain the default entry state. |

Record responsive behavior as a later verification concern, not a new screen. |
| C12 | Some additional screens show asset-heavy previews and polished thumbnail imagery, while Penpot screen boards intentionally use native shapes and text rather than screenshots. | Additional 01–32; Penpot board structural scan | Use source imagery for visual reference only. Keep Penpot boards editable with native controls; use image fills only for content thumbnails or deliberate visual assets, never for whole-screen backplates. |

## Decisions carried into P02–P04

1. The sitemap groupings are the global navigation source of truth.
2. Original high-detail concepts define the intended hierarchy and interaction density; additional screens fill task and state detail.
3. Gold/blue/green/amber/red are semantic tokens, not competing brand palettes.
4. Source animation assets and target preview assets must remain explicitly labeled.
5. A canonical screen may own multiple reference variants, but every variant must be linked and its deviation recorded.
